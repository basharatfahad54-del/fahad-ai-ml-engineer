TalentMatch AI: Resume Screening and Candidate Ranking

A recruitment decision-support platform that parses resumes and job descriptions, ranks candidates, and shows the evidence behind every score.

  • Python
  • FastAPI
  • NLP
  • scikit-learn
  • React
  • TypeScript
  • PostgreSQL
View the source on GitHub Discuss a similar project

The problem

Recruiters need help processing applications without handing final decisions to an opaque model. Candidate ranking must remain explainable, auditable, and open to human review.

How it works

  • Parses resumes and job descriptions into structured candidate and role data.
  • Scores six weighted components: required skills, experience, education, preferred skills, text similarity, and certifications.
  • Returns matched and missing skills plus component scores so a reviewer can inspect the evidence.
  • Keeps learned reranking offline after an experiment found no statistically significant NDCG@5 gain over the interpretable scorer.

Architecture

  • FastAPI and SQLAlchemy async API with JWT authentication, Pydantic, and Alembic migrations.
  • React, TypeScript, Vite frontend with React Router and TanStack Query.
  • PostgreSQL in Docker and SQLite for local development.
  • scikit-learn offline experiment on a synthetic corpus; it is not part of the request path.

Repository evidence

  • The repository README reports 51 API tests, 57 ML tests, and 14 web tests passing at the time of writing.
  • The authored reranker experiment is reported as statistically tied on NDCG@5 (p = 0.511), so the interpretable scorer remains shipped.
  • Protected attributes are structurally excluded from ranking features, and the system ranks and explains rather than auto-rejecting.

Limitations and scope

  • ML results come from a synthetic corpus, not real hiring outcomes.
  • Default hashing embeddings are an offline fallback; semantic matching improves with sentence-transformers or OpenAI embeddings.
  • There is no automated rejection or auto-screening by design.

Claims on this page are limited to the public repository scope. Metrics and capabilities are attributed to the project documentation rather than presented as independently audited benchmarks.
