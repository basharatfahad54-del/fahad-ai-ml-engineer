DevPilot AI: Sandboxed AI Developer Agent

A CLI AI developer agent built to demonstrate the control plane around an LLM: planning, tool calls, permissions, and auditable execution.

  • Python
  • LLM Agents
  • OpenRouter
  • SQLite
  • pytest
View the source on GitHub Discuss a similar project

The problem

Giving an LLM filesystem and shell access can make coding agents useful and dangerous. Many demos skip the workspace boundaries, command allowlists, approval gates, and audit trails needed to control model actions.

How it works

  • Generates a numbered plan with an OpenRouter-compatible LLM and falls back to a deterministic plan when the model is unavailable.
  • Exposes four tools: read_file, write_file, search_project, and safe_terminal.
  • Treats every model action as untrusted input and checks it through a deterministic permission layer before execution.
  • Persists task and tool-call history to SQLite with redacted arguments and approval decisions.

Architecture

  • CLI to agent loop to planner and LLM provider, then the permission gate, tool registry, and tool execution.
  • Write and execute actions are gated before execution and logged to SQLite before the next planning step.
  • Workspace boundaries reject path traversal, while shell commands are deny-by-default with a hard denylist.

Repository evidence

  • Open-source repository with 26 tests: 19 unit and 7 integration.
  • README documents a live sample run, the safety model, setup, limitations, and a GitHub Actions CI workflow.

Limitations and scope

  • There is no OS-level container sandbox; safe_terminal runs with the host user's privileges.
  • The agent loop is single-agent, without parallel tool execution or streaming.
  • Approval is CLI-only; the Streamlit dashboard is for visual demonstration.

Claims on this page are limited to the public repository scope. Metrics and capabilities are attributed to the project documentation rather than presented as independently audited benchmarks.
